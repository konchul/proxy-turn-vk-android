# qWDTT Benchmark Report

Методика, сырые данные и reproduсируемость всех замеров форка.
Обновлено: v1.4.4-qwdtt (MTU 1350, flood-режим).

## 1. Методика

- **Стенд**: KVM VPS 2 vCPU / 4 ГБ (Ubuntu 22.04, ядро 5.15), сервер закреплён
  на ядре 1 (`taskset -c 1`), генератор нагрузки — на ядре 0.
- **Инструмент**: `tools/loadgen` — синтетический клиент, говорящий протоколом
  qWDTT (HKDF-ключ из пароля → RTP-obfs AEAD → GETCONF_RAW/AUTH → сырые IP-пакеты).
- **Режимы**:
  - `flood` — односторонний поток: меряет чистый потолок сервера
    (unwrap → TUN write → forward) без ограничения echo-цикла;
  - `load` (echo) — полный цикл с RTT/потерями, как у реального клиента.
- **Замер CPU**: дельта utime+stime из `/proc/PID/stat` (jiffies), нормировано
  на длительность и CLK_TCK → % одного ядра.
- **Метрики**: achieved_pps и Mbit/s по факту приёма; потери — доля
  недошедших; RTT — по сэмплам 1/64 пакетов с меткой времени в payload.

## 2. Сравнение версий (flood, MTU по версии, 0% потерь)

base = сборка апстрима SpaceNeuroX/proxy-turn-vk-android;
opt5 = этот форк (итерации: hot-path, крипто-слой, батчинг syscalls);
GSO = opt5 + `-tun-gso`.

### Выводы

- При равной нагрузке форк тратит **на 15–19% CPU меньше** апстрима
  (100k pps: 71.7% → 58.2%).
- Потолок: база захлёбывается на ~92k pps (цель 300k), форк держит
  **114–117k pps ≈ 1.23–1.26 Гбит/с**.
- AES-256-GCM быстрее ChaCha20 на том же бинарнике (аппаратный AES).
- GSO добавляет −3–5% CPU на UDP; на TCP-трафике (не входит в этот тест)
  выигрыш больше за счёт GSO-суперкадров.

## 5. Воспроизведение

```bash
# 1. Бинарники: собрать из репо (server/ и tools/loadgen/)
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o wdtt-server ./server
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o loadgen ./tools/loadgen

# 2. Скрипт серий (подставить свои DIR/PASS/порты) — см. bin/bench-v3.sh
#    Сервер: taskset -c 1, loadgen: taskset -c 0, режим -mode flood.
# 3. CPU: дельта /proc/PID/stat (utime+stime) до/после точки.
```

Юнит-тесты сегментации GSO: `go test ./server -run TestSegment` (4 теста PASS).
